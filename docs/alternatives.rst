Compare with other tools
========================

Several tools put Java API documentation into Sphinx, and a plain Javadoc site is
always an option. The other tools were assessed in October 2026 from their
documentation and source code, without running them. If something is out of date,
please `open an issue <https://github.com/r4sky0/sphinx-java-autodoc/issues>`_.

When to choose which
--------------------

**sphinx-java-autodoc** fits when you want guides and the API reference in one
Sphinx site, with links that resolve and inherited documentation that stays in
place. You need JDK 25 to extract, although your library can target Java 17 or
21. See :doc:`compatibility` for tested versions and known limits.

**sphinx-javadoc-xml** fits when you already produce XML doclet output in your
build and want a page that looks like classic Javadoc, and missing ``{@link}``
targets and inherited comments don't matter for your API.

**javasphinx** isn't a good choice for new projects. Its own README says it should
be used for historical purposes only, and it can't parse Java newer than 8.
Several forks exist, but none is released under a new name.

**Doxygen with Breathe or Exhale** fits when one site documents C or C++ next to
Java and you already run Doxygen. Its Java support is secondary, and Java objects
appear as C++ ones in Sphinx.

**A separate Javadoc site** fits when your readers expect the standard Javadoc
layout and your guides can live elsewhere. Sphinx pages can link to it with
`sphinx.ext.extlinks <https://www.sphinx-doc.org/en/master/usage/extensions/extlinks.html>`_.
`sphinx-javalink <https://github.com/bluekeyes/sphinx-javalink>`_ did this with
Java-aware roles but hasn't changed since 2016.

The :doc:`design notes <design>` explain why this extension uses the JDK instead
of these approaches.
